# Movies API V4

Учебный REST API на FastAPI для управления фильмами.

Для хранения данных используется MongoDB, взаимодействие с базой данных выполняется с помощью PyMongo. Валидация входных и выходных данных осуществляется через Pydantic.

## Установка и запуск

Для запуска проекта необходимы Docker и Docker Compose.

1. Соберите и запустите контейнеры:

   ```bash
   docker compose up --build -d
   ```

2. Проверьте состояние контейнеров:

   ```bash
   docker compose ps
   ```

3. Откройте Swagger UI:

   http://localhost:8000/docs

Для просмотра логов приложения:

```bash
docker compose logs -f api
```

Для остановки контейнеров:

```bash
docker compose down
```

## Docker Compose

Для запуска проекта используется Docker Compose, который управляет двумя сервисами:

- `api` — FastAPI-приложение;
- `mongo` — сервер MongoDB версии 7.

Конфигурация находится в файле `compose.yaml`:

```yaml
services:
  mongo:
    image: mongo:7
    restart: unless-stopped
    volumes:
      - mongo-data:/data/db

  api:
    build: .
    restart: unless-stopped
    ports:
      - "8000:8000"
    environment:
      MONGO_URL: mongodb://mongo:27017
      MONGO_DB_NAME: movie_api
    depends_on:
      - mongo

volumes:
  mongo-data:
```

Для подключения к MongoDB используются переменные окружения:

- `MONGO_URL` — адрес MongoDB;
- `MONGO_DB_NAME` — название базы данных.

Внутри Docker Compose сервисы взаимодействуют по своим именам. Поэтому API подключается к MongoDB по адресу `mongodb://mongo:27017`.

Docker Volume `mongo-data` используется для постоянного хранения данных MongoDB. Данные сохраняются при остановке и удалении контейнеров.

## Эндпоинты

| Метод | Путь | Параметр | Описание |
|---|---|---|---|
| POST | `/` | JSON в теле запроса | Добавить новый фильм. Возвращает созданную запись с идентификатором. |
| GET | `/` | — | Получить список всех фильмов. |
| GET | `/{movie_id}` | `movie_id` в пути | Получить фильм по идентификатору. |
| PUT | `/{movie_id}` | `movie_id` в пути, JSON в теле | Полностью обновить информацию о фильме. Возвращает обновлённую запись. |
| DELETE | `/{movie_id}` | `movie_id` в пути | Удалить фильм по идентификатору. |

## Структура данных

Каждая запись о фильме содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | `int` | Уникальный идентификатор фильма. |
| `name` | `str` | Название фильма. |
| `plot` | `str` | Сюжет фильма. |
| `genres` | `list[str]` | Список жанров фильма. |
| `casts` | `list[str]` | Список актёров. |

Пример JSON для добавления или обновления фильма:

```json
{
  "name": "Космическая одиссея 2001 года",
  "plot": "Обезьяны увидели монолит и стали эволюционировать.",
  "genres": ["Научная фантастика", "Триллер"],
  "casts": ["Кир Дулли", "Гари Локвуд"]
}
```

Идентификатор `id` создаётся автоматически при добавлении фильма и не передаётся в теле запроса.

## Валидация (Pydantic)

Для валидации данных используются Pydantic-схемы:

- `MovieResponse` — схема входящих данных.
- `MovieDB` — схема данных фильма, возвращаемых API.

Правила валидации:

- `name` и `plot` — обязательные непустые строки.
- `genres` — обязательный непустой список строк.
- `casts` — обязательный непустой список строк.

При передаче некорректных данных возвращается HTTP 422 Validation Error.

При попытке получить, обновить или удалить фильм с несуществующим идентификатором возвращается HTTP 404 с сообщением `Movie not found`.

## База данных (MongoDB)

Для хранения информации используется MongoDB.

Приложение работает с двумя коллекциями:

**Коллекция `movies`**

Содержит документы с информацией о фильмах:

- `id` — уникальный числовой идентификатор фильма;
- `name` — название фильма;
- `plot` — сюжет фильма;
- `genres` — массив жанров;
- `casts` — массив актёров;
- `_id` — автоматически создаваемый MongoDB идентификатор документа.

Поле `_id` используется MongoDB для внутренней идентификации документа и не возвращается API. В качестве идентификатора фильма используется отдельное поле `id`.

Взаимодействие с MongoDB выполняется с помощью PyMongo. Для получения, добавления, обновления и удаления документов используются стандартные методы коллекций.

## HTTP-статусы

| Код | Описание |
|---|---|
| `200` | Успешное получение или обновление данных. |
| `201` | Фильм успешно добавлен. |
| `204` | Фильм успешно удалён. |
| `404` | Фильм с указанным идентификатором не найден. |
| `422` | Ошибка валидации входных данных. |
